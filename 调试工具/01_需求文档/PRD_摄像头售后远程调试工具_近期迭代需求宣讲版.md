## 1. 迭代背景

当前摄像头售后远程调试工具已经具备设备查询、设备信息查看、实时画面、基础控制、物模型联调和指令日志等核心能力。随着客服团队试用深入，原型需要进一步补齐真实售后场景中的几个关键能力：

1. 客服需要在调试过程中清晰知道设备当前固件是否为最新版本，并在非最新时具备固件升级入口。
2. 售后管理人员需要追溯每个客服对某台设备做了什么调试操作、下发了哪些指令。
3. MVP 原型需要与 V1.0 原型保持更接近的导航和记录查看方式，便于统一向团队说明核心链路。
4. 基础控制模块需要更贴近真实设备操作样式，降低客服理解成本。
5. 设备查询当前只覆盖国内查询，后续需要支持中国区、北美区、欧洲区、亚太区四大区设备查询。

本轮迭代以原型完善和需求确认为主，不直接定义完整后台实现方案；其中 MVP 原型重点补齐调试记录、区域化查询和基础控制体验，V1.0 原型重点补齐调试记录详情与固件升级表达。

## 2. 迭代目标

### 2.1 业务目标

1. 提升客服远程调试过程中的信息完整性。
2. 降低客服误判设备固件版本、设备区域和可调试能力的风险。
3. 建立可追溯的客服调试行为记录模型。
4. 支持四大区设备查询，为海外设备售后调试做准备。
5. 统一 MVP 与 V1.0 原型的核心交互表达，方便需求评审和研发拆解。

### 2.2 产品目标

1. 在设备查询链路中加入区域选择和区域节点展示。
2. 在固件版本字段中加入固件最新状态判断和升级入口。
3. 在调试记录中记录客服、设备、调试功能、指令日志和结果。
4. 调试记录详情以日志格式展示该客服当次调试会话的所有指令日志。
5. MVP 原型采用左侧菜单栏布局，调试记录独立为一个页面。
6. 基础控制模块按开关、枚举、按钮三类控件清晰组织。

| 角色 | 核心诉求 | 本轮相关能力 |

## 5. 核心流程

### 5.1 区域化设备查询流程

1. 客服进入设备调试页面。
2. 客服选择设备所属区域：中国区、北美区、欧洲区或亚太区。
3. 客服输入设备 ID / VUID。
4. 客服点击“查询设备”。
5. 系统按所选区域路由到对应设备查询网关。
6. 查询成功后展示设备基础信息、所属区域、区域节点、产品型号、固件版本和在线状态。
7. 系统基于机型切换对应调试能力。
8. 系统查询对应区域下的 MQTT / TCP 控制链路状态。
9. 查询过程写入本次会话指令日志。

### 5.2 固件版本判断流程

1. 设备查询成功后，系统通过设备 ID / VUID 查询设备当前固件版本。
2. 系统查询对应产品型号和区域下的服务器最新固件版本。
3. 若当前版本等于最新版本，固件版本字段展示“最新”标签。
4. 若当前版本低于最新版本，固件版本字段展示“固件升级”按钮。
5. 客服点击“固件升级”后，系统下发固件升级指令。
6. 指令日志记录 current、target、requestId、region、node。
7. 设备回调成功后，固件版本更新为最新版本，并展示“最新”标签。

### 5.3 调试记录查看流程

1. 客服完成一次设备调试。
2. 系统按调试会话生成一条调试记录。
3. 调试记录列表展示操作人、设备、调试功能、指令数量、高危操作数量、结果和时间。
4. 售后管理人员或售后技术支持点击“详情”。
5. 系统以日志格式展示该用户当次调试会话中的所有指令日志。
6. 详情页保留复制按钮，用于复制日志给研发或工单备注。
7. 详情页不提供下载按钮，避免原型阶段引入文件下载和权限扩展。

### 5.4 MVP 页面导航流程

1. MVP 原型使用左侧菜单栏。
2. 菜单包含“设备调试”和“调试记录”。
3. 点击“设备调试”进入远程调试主工作台。
4. 点击“调试记录”进入独立调试记录页面。
5. 调试记录详情使用弹窗展示，不与设备调试主工作台混在同一界面。

## 6. 功能需求

### 6.1 设备查询支持四大区

| 需求项 | 说明 |
| --- | --- |
| 区域选择 | 设备查询表单增加区域选择控件 |
| 区域选项 | 中国区、北美区、欧洲区、亚太区 |
| 查询参数 | 设备查询接口需携带 region |
| 查询路由 | 后端根据 region 路由到对应区域节点 |
| 结果展示 | 基本信息中展示所属区域、区域节点 |
| 日志记录 | 查询日志中记录 region、node、endpoint 或 route |
| 异常提示 | 设备不存在、区域选错、区域服务不可用时需给出明确提示 |

建议区域编码：

| 区域 | 编码 | 节点示例 |
| --- | --- | --- |
| 中国区 | CN | cn-east |
| 北美区 | NA | us-west |
| 欧洲区 | EU | eu-central |
| 亚太区 | APAC | ap-southeast |

### 6.2 固件版本与固件升级

| 状态 | 页面表现 | 操作 |
| --- | --- | --- |
| 未查询 | 固件版本显示未查询或占位 | 不展示升级按钮 |
| 当前为最新 | 固件版本旁展示“最新”标签 | 不展示升级按钮 |
| 当前非最新 | 展示当前版本和“固件升级”按钮 | 支持点击升级 |
| 升级中 | 按钮进入升级中状态 | 禁止重复点击 |
| 升级成功 | 固件版本更新为最新版本 | 展示“最新”标签 |
| 升级失败 | 日志记录失败原因 | 保留升级入口或提示重试 |

日志字段建议：

| 字段 | 说明 |
| --- | --- |
| deviceId / vuid | 设备标识 |
| region | 区域编码 |
| node | 区域节点 |
| currentVersion | 当前固件版本 |
| latestVersion | 服务器最新版本 |
| requestId | 升级请求 ID |
| operator | 操作人 |
| result | 成功、失败、超时 |
| callbackTime | 设备回调时间 |

### 6.3 调试记录

调试记录按“客服一次调试会话”记录，而不是按单条指令记录。列表用于管理和检索，详情用于查看该会话内的全部指令日志。

#### 6.3.1 列表字段

| 字段 | 说明 |
| --- | --- |
| 调试时间 | 本次调试开始或结束时间 |
| 操作人 | 客服姓名 / 账号 / 角色 |
| 设备 | 设备 ID / VUID |
| 区域 | 设备查询时选择的区域 |
| 调试功能 | 本次会话涉及的主要功能，如设备查询、实时画面、基础控制、固件升级 |
| 指令数量 | 本次会话下发和回调的指令总数 |
| 高危操作 | 固件升级、重启、格式化 TF 卡等高风险操作数量 |
| 结果 | 成功、部分失败、失败、超时 |
| 操作 | 查看详情 |

#### 6.3.2 详情内容

详情仅展示该用户当次调试会话的所有指令日志，采用日志格式展示。

日志格式建议：

```text
[2026-08-08 10:28:14] [系统] 林晓/客服 | 设备 VSTK059176NZFWL 基础状态查询成功 region=CN node=cn-east
[2026-08-08 10:28:16] [系统] 林晓/客服 | MQTT 控制链路在线 requestId=req_1723084096
[2026-08-08 10:29:02] [指令] 林晓/客服 | 设置运动侦测=开启 requestId=req_1723084142
[2026-08-08 10:29:03] [回调] 林晓/客服 | 设置成功 ack=success requestId=req_1723084142
```

详情操作：

1. 保留“复制”按钮。
2. 取消“下载”按钮。
3. 暂不提供日志筛选和导出，后续按管理诉求扩展。

### 6.4 MVP 基础控制模块

MVP 基础控制模块按控件类型组织，客服只看到可理解的设备操作，不暴露物模型字段名。

#### 开关样式

| 功能 | 状态 |
| --- | --- |
| 运动侦测 | 开启 / 关闭 |
| 远程休眠 | 开启 / 关闭 |
| 声音 | 开启 / 关闭 |
| 上下翻转 | 开启 / 关闭 |

#### 枚举样式

| 功能 | 枚举值 |
| --- | --- |
| 工作模式 | 常电模式 / 低功耗模式 |
| 夜视模式 | 自动模式 |

#### 按钮样式

| 功能 | 说明 |
| --- | --- |
| 格式化 TF 卡 | 高危操作，正式版本需二次确认 |
| 重启 | 高危操作，正式版本需二次确认 |

### 6.5 页面滚动

1. 调试工具主内容区需支持上下滚动。
2. 当信息区、画面区、控制区和日志区内容超出可视范围时，用户可以继续向下查看。
3. 滚动能力不应破坏左侧导航和顶部操作区的稳定性。

## 7. 数据与接口建议

### 7.1 区域化设备查询接口

```http
POST /api/debug/device/query
Content-Type: application/json
```

请求参数：

```json
{
  "region": "CN",
  "deviceId": "VSTK059176NZFWL"
}
```

响应字段建议：

```json
{
  "deviceId": "VSTK059176NZFWL",
  "region": "CN",
  "regionName": "中国区",
  "regionNode": "cn-east",
  "productType": "婴儿看护",
  "productModel": "BabyCare-Cam",
  "onlineStatus": "online",
  "controlChannel": "MQTT",
  "firmwareVersion": "sys_1.0.8",
  "latestFirmwareVersion": "sys_1.0.9"
}
```

### 7.2 调试记录接口

调试记录建议按 session 维度保存。

```http
GET /api/debug/sessions
GET /api/debug/sessions/{sessionId}/logs
```

调试会话字段建议：

| 字段 | 说明 |
| --- | --- |
| sessionId | 调试会话 ID |
| operatorId | 操作人 ID |
| operatorName | 操作人姓名 |
| operatorRole | 操作人角色 |
| deviceId | 设备 ID / VUID |
| region | 区域编码 |
| regionNode | 区域节点 |
| featureSummary | 调试功能摘要 |
| commandCount | 指令数量 |
| highRiskCount | 高危操作数量 |
| result | 调试结果 |
| startedAt | 开始时间 |
| endedAt | 结束时间 |

指令日志字段建议：

| 字段 | 说明 |
| --- | --- |
| logId | 日志 ID |
| sessionId | 调试会话 ID |
| timestamp | 日志时间 |
| level | 系统、指令、回调、错误 |
| operator | 操作人 |
| feature | 调试功能 |
| command | 指令名称 |
| payload | 指令参数摘要 |
| requestId | 请求 ID |
| result | 执行结果 |
| rawLog | 原始日志文本 |

## 8. 验收标准

### 8.1 设备查询

1. MVP 设备查询表单可选择四大区。
2. 查询成功后，基本信息展示所属区域和区域节点。
3. 查询日志包含 region 和 node。
4. 切换不同区域后再次查询，日志和基本信息同步更新。
5. V1.0 原型不受本轮 MVP 区域化查询改动影响。

### 8.2 固件升级

1. 当前固件为最新时展示“最新”标签。
2. 当前固件非最新时展示“固件升级”按钮。
3. 点击固件升级后写入指令日志。
4. 升级成功后更新固件版本，并展示“最新”标签。
5. 固件升级日志包含当前版本、目标版本、requestId 和区域上下文。

### 8.3 调试记录

1. 调试记录作为独立页面展示。
2. 列表可看出操作人、设备、调试功能、结果和时间。
3. 点击详情后，以日志格式展示该用户当次所有指令日志。
4. 详情保留复制按钮。
5. 详情不展示下载按钮。

### 8.4 基础控制

1. 开关类功能使用开启 / 关闭样式。
2. 枚举类功能使用选项切换样式。
3. 高危操作使用按钮样式。
4. 控制操作均写入指令日志。

## 9. 非本轮范围

1. 不补齐知识库功能。
2. 不补齐完整用户 App 授权闭环。
3. 不建设日志下载能力。
4. 不建设高危操作审批流。
5. 不建设多设备批量调试。
6. 不调整 V1.0 的四大区查询交互，除非后续单独确认。
7. 不对接真实生产区域网关，本轮原型仅表达交互和字段。

## 10. 研发拆解建议

| 优先级 | 需求 | 说明 |
| --- | --- | --- |
| P0 | 区域化设备查询 | 后续海外设备调试的前置能力 |
| P0 | 调试记录 session 模型 | 审计留痕和售后追溯的基础 |
| P0 | 指令日志结构化 | 支撑详情查看、复制和后续检索 |
| P1 | 固件版本判断 | 提升客服判断效率 |
| P1 | 固件升级入口 | 与版本判断联动，高危操作需控制 |
| P1 | MVP / V1.0 导航一致性 | 降低宣讲和评审理解成本 |
| P2 | 日志筛选和导出 | 后续按管理诉求扩展 |
| P2 | 知识库联动 | 后续与常见问题处理方案结合 |

## 11. 风险与待确认事项

| 问题 | 风险 | 建议 |
| --- | --- | --- |
| 四大区命名和编码是否与后台一致 | 原型和接口实现可能不一致 | 与平台服务端确认区域枚举 |
| 同一设备 ID 是否可能跨区重复 | 查询结果可能误判 | 以 region + deviceId 作为查询唯一上下文 |
| 固件最新版本是否按区域区分 | 不同区域发布节奏可能不同 | 固件查询接口需携带 region |
| 调试记录保存周期 | 存储成本和合规要求不明确 | 先按 1 个月或公司审计规范确认 |
| 日志是否包含敏感信息 | 复制日志可能带出隐私数据 | payload 摘要需脱敏 |
| 高危操作上线策略 | 误操作风险 | 正式环境保留二次确认，必要时加权限控制 |

## 12. 需求宣讲提纲

1. 当前工具已经跑通远程调试主链路，本轮重点是补齐真实售后使用中的“可追溯、可判断、可跨区”。
2. 对客服来说，最明显变化是查询设备时可以选择区域，固件版本能直接判断是否最新，基础控制更像真实设备操作。
3. 对售后管理来说，调试记录从“页面临时日志”升级为“按客服当次调试会话追溯”。
4. 对研发来说，本轮关键不是界面复杂度，而是区域参数、session 记录、结构化指令日志和固件版本判断接口。
5. 本轮明确不做知识库、完整 App 授权、下载和审批流，避免范围失控。
6. 宣讲后需要重点确认四大区枚举、调试记录保存周期、固件版本是否按区域发布，以及高危操作上线策略。
