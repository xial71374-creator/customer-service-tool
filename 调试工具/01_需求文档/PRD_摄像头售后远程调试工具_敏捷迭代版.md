## 1. 项目背景

现有摄像头售后调试依赖较底层的工具和指令能力，客服和售后技术支持在处理用户问题时，难以快速远程查看设备状态、画面和执行基础调试操作。

本项目计划建设一个面向售后场景的 Web 远程调试工具，通过用户 App 授权和 MQTT 连接设备，帮助客服和售后技术支持远程查看设备信息、实时画面、执行设备控制并记录调试过程。

为了降低首期交付复杂度，项目采用敏捷迭代方式推进。MVP 版本不建设账号体系、用户授权和完整后台能力，先验证最核心的远程调试链路和婴儿看护设备物模型联调能力是否可用；后续版本逐步补齐账号、授权、日志留存、视频增强、固件升级、权限体系和系统对接等能力。

## 2. 产品目标

### 2.1 总体目标

1. 建立摄像头设备远程调试能力。
2. 提高售后问题定位效率。
3. 降低研发介入售后问题的频率。
4. 提升用户问题解决速度和满意度。
5. 将原 CGI 调试能力逐步迁移为标准化 MQTT 调试能力。

### 2.2 迭代原则

1. MVP 优先跑通核心链路，不追求完整后台能力。
2. 每个版本都应可独立验收和上线。
3. 高风险操作分阶段开放，先控制范围，再补权限和二次确认策略。
4. 设备能力按物模型和功能集动态展示，避免写死功能入口。
5. MVP 阶段用于内部联调验证，不做用户授权；V1.0 起所有涉及用户隐私和设备控制的能力均需基于用户授权。

## 4. MVP 版本

### 4.1 版本目标

MVP 版本用于验证摄像头设备远程调试闭环：客服无需登录账号，直接输入设备 VUID 查询设备，系统通过 MQTT 连接设备，使用 WebRTC 展示实时画面。首批覆盖婴儿看护机型和 BK 机型，系统需根据设备机型、物模型和功能集动态展示设备信息、实时画面控制、基础控制入口和物模型联调面板。客服可查看设备基本信息、网络信息、机型状态摘要，并通过物模型联调面板跑通已定义的属性读取、属性设置和服务调用。设备事件不作为主动联调项展示，仅在设备触发后进入本次会话日志。MVP 阶段不做用户授权能力。

### 4.2 用户范围

| 用户 | 说明 |
| --- | --- |
| 客服/售后技术支持 | 使用 Web 工具发起远程调试 |
| 用户 | MVP 阶段不参与授权流程 |

### 4.3 功能范围

1. 输入设备 VUID。
2. 查询设备基础状态。
3. 建立 MQTT 连接。
4. 使用 WebRTC 查看单路实时画面。
5. 查看设备基本信息。
6. 查看设备网络信息。
7. 查看机型状态摘要：婴儿看护机型展示检测与报警信息，BK 机型展示状态与能力信息。
8. 在实时画面区展示画面只读信息和画面快捷控制。
9. 根据机型展示对应物模型联调面板。
10. 支持物模型属性读取。
11. 支持物模型可写属性设置。
12. 支持物模型服务调用。
13. 支持设备事件触发后在指令日志中展示。
14. 执行基础远程调试功能。
15. 执行云台基础控制。
16. 展示本次调试指令日志。
17. 客服主动断开连接。

### 4.4 设备信息

MVP 需展示设备基本信息、网络信息和机型状态摘要。状态摘要按物模型和功能集动态展示，不支持的能力不展示或显示为不支持。

#### 基本信息

| 字段 | 说明 |
| --- | --- |
| VUID | 设备唯一标识 |
| 产品类型 | 如常电 Wi-Fi、4G、电池类等 |
| 产品型号 | 设备型号 |
| 固件版本 | 当前固件版本 |
| 芯片型号 | 设备芯片型号 |
| 硬件版本 | 设备硬件版本 |
| 设备在线时长 | 设备本次在线持续时间 |
| SD 总容量 | 存储卡总容量，若设备不支持则不展示 |
| SD 可用容量 | 存储卡可用容量，若设备不支持则不展示 |
| SD 健康状态 | 存储卡健康状态，若设备不支持则不展示 |
| 解码模式 | H.264、H.265 等 |
| 在线状态 | 在线、离线 |

#### 网络信息

| 字段 | 说明 |
| --- | --- |
| 配网方式 | Wi-Fi、4G、有线等 |
| 信号强度 | 若设备支持则展示 |
| SSID | Wi-Fi 名称，按隐私要求展示 |
| IP 信息 | 局域网或公网相关信息 |
| P2P 状态 | 可用、不可用、不适用 |

#### 机型状态摘要

| 字段 | 说明 |
| --- | --- |
| 婴儿看护检测与报警 | 哭声、面部遮挡、口鼻遮挡、趴睡、踢被、睡眠活动、温湿度异常、精彩瞬间等 |
| BK 状态与能力 | 工作模式、夜视模式、运动侦测开关、侦测灵敏度、侦测频率、麦克风音量、电池电量、TF 卡状态等 |
| 不支持能力 | 对应机型不支持的能力不展示，或明确展示为不支持 |

### 4.5 基础设备控制

MVP 需保留远程调试设备的基础功能，并按机型物模型和功能集动态展示基础控制入口；不支持的功能不展示或置灰。基础控制区只承载设备控制、婴儿看护检测、看护与音频、云台等调试入口。画面相关快捷控制归属实时画面区，不在右侧基础控制区重复展示。

基础控制区需支持：

1. 工作指示灯、系统提示音等设备控制。
2. 哭声检测、面部遮挡、口鼻遮挡、趴睡监测、踢被检测、AI 自动抓拍等婴儿看护检测。
3. 双向对讲、安抚开关、安抚音频、温湿度查询、虚拟围栏、清空围栏等看护与音频能力。
4. 云台方向、步长读取/设置、一键归位、转动模式、停止转动等云台能力。
5. 电池信息、麦克风、运动侦测、Wi-Fi、TF 卡等 BK 机型能力。

实时画面区需支持：

1. 展示画面只读信息，如协议、流类型、码流/分辨率、帧率、码率等。
2. 放置画面快捷控制，如水平翻转、垂直翻转、夜视模式、高清 / 流畅模式、WDR、OSD 水印。
3. 画面快捷控制点击后仍需通过物模型字段同步，并在指令日志中记录下发与回调。

### 4.6 物模型联调

MVP 需要将首批机型设备物模型跑通，支持按物模型动态渲染属性和服务。婴儿看护机型需覆盖完整婴儿看护物模型；BK 机型需覆盖电池、麦克风、设备信息、重启、移动侦测、Wi-Fi、夜视模式和 TF 卡等物模型。事件属于设备触发后的被动上报，不放在物模型联调列表中作为主动操作项。

物模型联调区采用快捷入口卡片样式展示，支持搜索和功能分类下拉筛选。分类下拉默认选择“全部”。客服切换分类后，仅展示该功能分类下的可联调属性和服务。

物模型卡片面向客服操作，不展示唯一标识符、数据类型、访问模式、属性/服务标签、快捷同源等技术字段；卡片仅展示物模型名称和对应操作控件。标识符、数据类型、访问模式等信息仅用于内部映射、日志和接口调用。

#### 属性联调

1. 只读属性支持读取和展示当前值。
2. 可写属性支持在页面修改并通过 MQTT 下发。
3. 布尔型属性展示开关控件。
4. 枚举型属性展示下拉选择控件。
5. 数值型属性展示输入控件。
6. 字符串、结构体、数组型属性展示可输入或可查看的文本控件。
7. 密码等敏感字段不得明文展示，默认脱敏。
8. 已在顶部设备信息、网络信息、存储信息或机型状态摘要中展示的只读属性，不在物模型联调区重复展示。
9. 未在顶部信息区展示的只读属性需展示在物模型联调区，并提供读取入口。
10. 画面相关只读属性优先展示在实时画面区；若未在实时画面区展示，则可在物模型联调区展示读取入口。

#### 服务联调

1. 服务类物模型展示调用按钮。
2. 调用服务时记录 requestId、服务标识符、下发时间和回调结果。
3. 重启、恢复出厂、格式化 SD 卡等高敏服务在 MVP 原型中仅做模拟联调，正式环境需二次确认后下发。
4. MVP 不做审批流。

#### 事件展示

1. 事件不作为客服主动操作项展示。
2. 设备事件触发后进入本次会话日志。
3. 日志需展示事件标识符、触发时间和 payload 摘要。
4. MVP 不做事件长期保存。

| 云台 | 云台方向控制、停止、一键回中、步长角度、旋转模式、当前位置等 |

| 系统服务与事件 | 设备上线/离线、工作模式切换、重启完成、固件升级进度、恢复出厂日志等 |

| 类别 | 说明 |

### 4.7 云台基础控制

若设备物模型支持云台能力，MVP 需支持基础云台控制：

1. 上。
2. 下。
3. 左。
4. 右。
5. 左上。
6. 右上。
7. 左下。
8. 右下。
9. 停止。
10. 步长读取和设置，包括水平步长、垂直步长。

云台相关快捷操作需集中展示在云台控制区下方，不放在物模型联调列表中作为主要入口重复暴露。物模型联调区仍可按分类展示云台相关字段，用于完整联调验证。

### 4.8 指令日志

MVP 日志只展示本次页面会话中的过程，不做长期保存。

日志内容包括：

1. 查询设备。
2. MQTT 连接。
3. WebRTC 拉流。
4. MQTT 断开。
5. 指令下发。
6. 设备回调。
7. 指令失败或超时。
8. 物模型属性读取、属性设置、服务调用、设备事件回调。

2. 不做账号体系。
3. 不做角色权限。
4. 不做用户授权。
5. 不做授权申请理由。
6. 不做用户 App 授权弹窗。
7. 不做调试记录页。
8. 不做知识库。
9. 不做设置页。
10. 不做历史录像。
11. 不做多镜头。
12. 不做截图、录制、下载。
13. 不做日志下载。
14. 不做日志长期保存。

### 4.10 MVP 页面结构

MVP 只有一个页面：设备远程调试页。

页面区域包括：

1. 顶部状态区：工具名称、设备连接状态、刷新、断开连接。
2. 查询区：设备 VUID、查询并连接设备。
3. 设备信息区：展示基本信息、网络信息、机型状态摘要。
4. 实时画面区：展示单路实时画面、画面只读信息和画面快捷控制。
5. 基础控制区：展示 MVP 支持的设备、看护、音频、云台等基础调试按钮。
6. 云台控制区：展示云台方向控制、步长读取/设置、一键归位、转动模式和停止转动。
7. 物模型联调区：按机型展示属性和服务，采用快捷入口卡片样式，支持搜索和功能分类下拉筛选，默认展示全部。
8. 指令日志区：展示本次调试过程日志。

### 4.11 MVP 验收标准

1. 输入 VUID 后能查询设备基础信息。
2. 点击连接设备后能建立 MQTT 连接。
3. WebRTC 拉流成功后能查看设备实时画面。
4. 能展示设备基本信息、网络信息、存储信息和机型状态摘要。
5. 实时画面区能展示画面只读信息，并可执行画面快捷控制。
6. MQTT 连接成功后能执行 MVP 范围内的基础控制。
7. 支持云台设备执行方向控制、步长读取/设置、一键归位、转动模式和停止转动。
8. 首批机型物模型中的只读属性可按规则读取并展示：顶部已展示的不重复展示，未展示的进入物模型联调区。
9. 首批机型物模型中的可写属性可修改并生成 MQTT 下发日志。
10. 首批机型物模型中的服务可调用并展示回调。
11. 设备事件触发后可在指令日志中查看最近回调。
12. 客服主动断开后停止实时画面和设备控制。
13. MQTT 指令成功、失败、超时均有日志反馈。
14. 全流程无需登录账号即可完成验证。

## 5. V1.0 基础售后调试版本

### 5.1 版本目标

在 MVP 核心链路基础上，建设可用于日常售后场景的基础调试工具。V1.0 开始引入账号登录、调试记录、日志保存、截图录制、历史录像和更完整的设备功能控制。

1. 每次发起设备查询或授权申请时生成调试会话。
2. 调试会话需记录操作人、账号来源、设备 UID / VUID、开始时间、结束时间和结束原因。
3. 查询设备、申请授权、用户同意、用户拒绝、用户撤销、授权过期、MQTT 连接、断开连接、查看画面、截图、录制、下载、设备控制等行为均需记录操作日志。

#### 6.3.3 授权与连接稳定性

1. 平台侧先建设授权会话模型，支持记录授权申请、授权状态、授权有效期、结束原因和操作人。
2. 授权状态需覆盖待授权、授权中、已授权、用户拒绝、用户撤销、授权过期、已断开。
3. App 侧未完成接入前，可通过接口模拟或内部受控流程验证授权状态流转，但需明确标识为试用阶段方案。
4. 涉及用户隐私的实时画面、历史录像、下载和设备控制，需符合公司现有用户同意机制，不应仅依赖前端按钮判断。
5. 用户拒绝授权后，客服不可建立 MQTT 调试连接。
6. 用户撤销授权后，系统需立即停止实时画面、录像、下载和设备控制。
7. 授权过期后，系统需自动断开连接并记录结束原因。
8. 同一用户或同一设备存在有效调试授权时，其他客服再次申请需给出明确提示。
9. MQTT 连接失败时展示失败原因，并提供重试入口。
10. 客服主动断开连接后，调试会话需正常结束并保存记录。

1. 设备不存在时提示“未找到该设备，请确认 UID / VUID 是否正确”。
2. 设备未绑定用户时，不允许发起授权申请。
3. 设备离线时可展示设备信息，但不允许建立实时调试连接。

5. 指令下发后按钮进入执行中状态，避免客服重复点击。
6. 指令成功、失败、超时均需在页面和指令日志中展示。
7. 拉流失败时需展示失败原因，并提供刷新或重试入口。

#### 6.3.5 指令日志与调试记录

1. 指令日志支持展示全部日志和错误日志。
2. 指令日志需展示发送时间、回调时间、执行结果和 requestId。

6. 批量查询仅支持只读诊断，不允许批量高危操作。

## 12. 跨版本通用规则

### 12.1 授权规则

以下规则从 V1.0 开始适用，MVP 阶段不做用户授权。

1. 未授权不得查看实时画面。
2. 未授权不得控制设备。
3. 用户可拒绝授权。
4. 用户可随时撤销授权。
5. 授权过期后自动断开连接。
6. 授权申请理由需展示给用户。
7. 同一用户同一时间仅允许一个售后调试授权生效。

### 12.2 MQTT 指令规则

1. 所有设备控制均通过 MQTT 下发。
2. 每条指令需具备 requestId。
3. 指令需记录发送时间、回调时间、执行结果。
4. 指令超时需提示客服。
5. 指令失败需展示错误码和失败原因。
6. 页面状态以设备回调或重新拉取状态为准。

### 12.3 安全规则

1. Wi-Fi 密码、用户手机号等敏感信息需脱敏。
2. 截图、录像、下载行为需记录日志。
3. 高风险操作需二次确认。
4. 固件升级、格式化 SD 卡、设备重启属于高风险操作。
5. 当前规划不引入高风险操作审批流，高风险操作通过二次确认和日志留痕控制风险。

## 13. 已确认约束

1. MVP 不做真实设备重启执行，仅保留物模型服务模拟联调和日志展示。
2. MVP 不做用户授权。
3. MVP 实时画面使用 WebRTC 协议。
4. V1.0 支持历史录像查看，但不支持历史录像下载。
5. 固件升级完整流程放在 V1.5 版本，MVP 仅保留物模型服务模拟联调；升级事件触发后仅进入本次会话日志。
6. 参数型功能物模型字段已经定义完成。
7. 多镜头设备最多支持 4 路同时预览。
8. 日志、截图、录像保存周期不允许配置。
9. 高风险操作不需要审批，通过二次确认和日志留痕控制。
